# 浅白写作指导

这份指导把浅白草拟的原则转化为文档写作规范。它不是法律文本写作指南。目标是降低阅读摩擦，让项目文档更容易阅读、审查和维护，同时不牺牲准确性。

## 使用浅白语言

文档应让目标读者快速、准确地理解。

- 优先使用常见、直接、具体的词语。
- 避免冷僻词、装饰性表达和不必要的正式腔。
- 不要为了缩短文字而让意思变得含糊。
- 只在必要时使用技术术语。
- 如果读者可能不熟悉某个术语，首次出现时应解释。
- 能说清楚动作主体时，优先使用主动语态。
- 优先使用肯定句。
- 避免双重否定。
- 描述动作时，优先使用动词，少用名词化表达。

浅白不是随意、简略或不精确。浅白的前提是清楚和准确。

## 让文本容易跟随

文档结构应帮助读者顺着读下去，而不是频繁跳转和回看。

- 把相关信息放在一起。
- 先说明主要规则或主要观点，再说明例外和细节。
- 标题应直接说明本节内容。
- 每个段落只围绕一个主要意思展开。
- 如果一句话列出多个并列事项，优先改成列表。
- 定义、安装步骤、行为说明、限制和排障内容应分开写，避免混在同一段里。
- 当前段落能直接说明的信息，不要改成不必要的交叉引用。
- 如果必须引用其他位置，应说明读者为什么需要跳过去看。

好的结构应让读者扫一眼标题和列表，就能判断哪里有自己需要的信息。

## 控制句子长度

优先使用短而完整的句子。长句不是绝对不能用，但必须容易理解。

当一句话同时包含以下多项时，应考虑拆开：

- 多个条件。
- 多个动作。
- 多个例外。
- 多个结果。
- 较长的插入说明。
- 多层从句。
- 较长的并列列表。

相关词语应尽量靠近。主语不要离谓语太远，修饰语不要离被修饰对象太远。

如果句子因为列举并列事项而变长，应改用项目符号或编号步骤。

## 保持每个单元聚焦

每个文档单元只表达一个主要意思。

在本项目中，文档单元可以是章节、小节、段落、列表项或步骤。它不需要采用法律文本的形式。

- 一个章节应有一个清楚目的。
- 一个段落应展开一个主要意思。
- 一个列表项应描述一个事项、动作或条件。
- 一个编号步骤应包含一个主要动作。
- 如果一个单元同时解释安装、行为、例外和后果，应拆分。

聚焦的文档单元更容易审查，也更容易被工具检查。

## 发布前检查

发布文档前，检查以下问题：

- 目标读者是否清楚。
- 主要观点是否出现在次要细节之前。
- 每个章节、段落、列表项或步骤是否只有一个主要意思。
- 长句是否可以拆短，或改成列表。
- 技术术语是否必要，必要时是否已经解释。
- 否定表达是否可以改成肯定表达。
- 交叉引用是否必要，是否真的帮助读者。
- 简化之后，文本是否仍然准确。

## 用于润色工具

`garden-polish` 使用这份指导生成润色建议。它只在能给出明确替换时输出 edit。

每条 edit 固定包含 `file`、`oldText`、`newText`、`reason` 四个字段。工具不输出风险等级、评分或软规则检查结果。

如果工具发现问题但不能安全改写，应输出 finding，而不是猜测一个替换。
